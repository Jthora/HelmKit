## What this track is

The direct response to the project's stated priority — "crack Psionics foundationally" toward a working Mk3+ HelmKit, "however Psionics works" (mechanism-agnostic) — after a self-critique found that prior wiki-verification work (Track A's toolkit) mostly checked whether the wiki is *consistent with itself*, not whether psionics is real or how it works. This track is deliberately not more of that: it grounds claims in real-world literature instead of the wiki's paraphrase of it, builds the one statistical capability the Mk-ladder's own Mk3.0 gate names and nothing addressed, adds a way to rule out mundane explanations before trusting a positive result, and prepares (but does not yet run) a first real empirical touchpoint.

Full technical write-up: [`docs/psionic_engineering/computational_toolkit.md`](../../psionic_engineering/computational_toolkit.md). Plan file this track executed: `/Users/jono/.claude/plans/noble-frolicking-dijkstra.md` (local to the session that ran it, referenced here for provenance).

## What shipped (2026-08-05)

1. **Literature grounding** — [`docs/psionic_engineering/literature_grounding.md`](../../psionic_engineering/literature_grounding.md). Checked the wiki's F1/F2-adjacent citations (Storm et al. 2010 ganzfeld meta-analysis, Utts 1996 Star Gate assessment) against real primary/secondary sources via web search. Found: the "d≈0.14–0.20" ganzfeld citation (in both the wiki and our own `docs/falsification.md`) likely conflates an r-type effect size with Cohen's d, and cites a since-superseded larger effect size versus a smaller one from a more recent preregistered replication; the "p<10⁻²⁰" Star Gate aggregate, by contrast, checks out exactly against Utts' own reported figure. `tools/experiment_design.py` gained `GANZFELD_HIT_RATE_PRESETS` (a `--preset` flag on the `binom` subcommand) sourced from this doc. Closes the "recompute the wiki's cited effect size" backlog item from Track A.
2. **Dicke N² scaling test design** — new `required_replicates_for_dicke_test`/`dicke_scaling_effect_size`/`dicke_scaling_predictions` functions and a `dicke-scaling` CLI subcommand in `tools/experiment_design.py`. Directly targets `docs/mk_ladder.md`'s Mk3.0 G3 gate ("F7 + 2-emitter Dicke superradiance N² scaling test"), which nothing in the toolkit previously addressed. Statistical design only — reuses the existing one-sample power-analysis machinery; running this test for real is correctly gated behind Mk0.5→Mk2.5 per the ladder's no-skipping rule, not scheduled by this track.
3. **Confound-rejection tool** — new `tools/analyze_ambient_confounds.py`. Checks whether an ambient reference channel (RF survey, magnetometer/gradiometer) correlates with a biometric target channel beyond a circular-shift null, so a future dyadic/forced-choice result can be checked against "was this actually a shared external stimulus" before being treated as interesting. Deliberately contains **no SDR/radio invocation code at all** (verified by a dedicated test) rather than trying to constrain a transmit-capable device (HackRF One, per `docs/inventory.md`) to receive-only from inside the tool — capture is a separate, human-operated step. Reuses `analyze_dyadic_coherence.py`'s `analyze_dyadic` directly rather than duplicating its resample/surrogate-testing logic.
4. **Forced-choice pilot protocol (prepared, not run)** — [`docs/protocols/forced_choice_pilot.md`](../../protocols/forced_choice_pilot.md), following the existing `g2_hrv_validation.md`/`g2_oracle_device.md` conventions. Specifies a concrete blinding procedure (the AI must not see targets or individual guesses before scoring) and is honest that a realistic first-pilot trial count (~20–50) is far below what the literature-grounded presets from item 1 say is actually needed (587–3736 trials) — the pilot's purpose is to exercise the full pipeline once, honestly, not to reach a confident conclusion.
5. **Wiki correspondence** — [`docs/psionic_engineering/report_to_wiki_maintainers_2026-08-05.md`](../../psionic_engineering/report_to_wiki_maintainers_2026-08-05.md) augmented with item 1's finding, and a new [`wiki_correspondence_log.md`](../../psionic_engineering/wiki_correspondence_log.md) to track outreach as an ongoing record rather than a one-off. Still not sent — no email capability in this environment; sending remains a manual step.

All new code is tested (unit tests added to `tests/test_experiment_design.py`, new `tests/test_analyze_ambient_confounds.py`); see the computational toolkit doc for current pass counts.

## What this does NOT establish

Same discipline as the rest of this project's falsification framework: nothing here is evidence that psionics is real, and nothing here has touched real data. Every new statistical capability (Dicke-scaling, the literature presets) is a planning tool; every new analysis tool (confound rejection) has only run on synthetic self-test data; the pilot protocol has a documented procedure and zero completed sessions.
